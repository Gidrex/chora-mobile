# Chora с другой стороны: что мы уже построили (не зная этого) и какие фичи нужны

Читается после `concepts/claude-duet.md`. Там — разбор Duet; здесь — Chora,
увиденная через его оптику: что у нас уже есть из agent-стека, чего не хватает
до «проактивного агента на своих файлах» и в каком порядке это делать.

Факты ниже — из репозиториев на 2026-10-30: `chora` (CLI, `src/*.rs`, `README.md`,
`AGENTS.md`) и `chora-mobile` (Flutter + `rust/src/api.rs`, `.agents/*`).

---

## 1. Chora в одном абзаце

Chora — персональный органайзер на plain-markdown файлах в обычном git-репо
(`~/chora` по умолчанию): `notes/<project>/`, `events/YYYY-MM-DD.md`,
`events/repeatable/<weekday>.md`, `events/backlog/`, человеко-владеемый `index.md`
с контекстом и грифами. Два клиента одного хранилища: CLI на ПК (`chora`, Rust,
clap + TUI, фоновый git-sync без демонов) и мобильный апп (Flutter + Rust через
FRB, офлайн-first). Синк между ними сегодня — внешний (Syncthing-Fork на телефоне,
git-remote на ПК), очередь поручений ПК-агенту — `to-agent/*.md`.

---

## 2. Главный разворот: Chora уже наполовину Duet

Duet состоит из двух половин: **«руки в данных»** (коннекторы, VM, skills) и
**«голова с манерами»** (бриф, Tasks, апрувы, тишина по умолчанию).
Первую половину мы построили — просто в виде файлов, а не облака:

| Примитив Duet | Что уже есть в Chora | Где |
|---|---|---|
| Memory, общая для всех задач | `index.md`: human-owned контекст + `about` на путь; читается `chora index` | `chora/src/index.rs`, `README.md:59` |
| Clearance / права агента | `security: open\|restricted\|critical` + наследование longest-prefix; `--max-access` режет show/headers/add/override/index | `chora/src/cli.rs`, `AGENTS.md:41` |
| Machine-интерфейс для агентов | `chora help` (`skill`): короткая машинная сводка команд, всегда plain text, без пейджера | `chora/src/cli.rs:469` |
| JSON для скриптов | `--json` у `note show`, `event show`, `index` | `README.md:38` |
| Делегирование человеку → агенту | `to-agent/YYYY-MM-DD-<slug>.md` с `Date/Priority/Project + body` | `chora/src/store.rs:75` |
| Session log, переживающий падения | git-история + `sync.log` с timestamp-разделителями | `README.md:125`, `chora/src/sync.rs` |
| Scheduled reports (идея) | `manage_old_event`, repeatables, календарь с маркерами | `chora/src/calendar.rs`, config |
| Тихий фон без демонов | detached `setsid`-ребёнок: commit → pull --rebase → push; шелл возвращается мгновенно, сеть — никогда в foreground | `README.md:125`, `chora/src/git.rs` |
| Быстрые руки (аналог TTFT-заботы) | Мобильный бюджет: cold start <600мс, 0 лишних bridge-calls, один range-read (C7) | `.agents/architecture.md` |

То есть по духу Chora ближе к **Cowork** («руки в твоих файлах»), чем к Duet:
агенту изначально выданы машинный интерфейс, грифы и человеко-владеемая память.
Чего нет — всей второй половины: **проактивности, видимости задач и gate на действия**.
Это и есть список фич ниже. Хорошая новость: вторая половина почти целиком —
новые чтения и экраны поверх существующих файлов, а не новая инфраструктура.

## 3. Принципиальное ограничение: «No daemons» vs «always-on»

`chora/README.md:3` — «No daemons». Duet — always-on по определению.
Разрешение противоречия (фиксируем как решение, не как вопрос):

- Chora не становится демоном. Проактивность = **бриф в момент запуска** (CLI и mobile)
  + поручения ОС, которыми владеет пользователь (systemd timer / cron / запуск при
  логине на ПК), а не встроенный фоновый процесс.
- Это согласуется с твоей моделью: агент работает на ПК, **когда ты за ним**.
  Значит «проверки раз в часы» Duet превращаются в «проверки в моменты присутствия»:
  разблокировка, открытие терминала/апп, утро/вечер. Каденс — словами, как у Duet.
- Следствие: телефон никогда не выполняет задачи в фоне (non-goal из duet-файла
  сохраняется). Фоновая работа — только ПК; телефон — заказчик и контролёр.

## 4. Фичи: протокол `to-agent/` v2 (ядро всего остального)

Сегодня задача — fire-and-forget текстовый файл без статуса и типа.
До «Tasks tab» не хватает протокола. Предложение (менять `store.rs` + `api.rs` + UI разом):

- **F1. Статусы.** Поле `Status:` в шапке файла:
  `new → taken → done` и боковая ветка `needs-approval → (approved → done | denied → new)`.
  Переходы только вперёд; закрывает задачу только человек (как у Duet: агент предлагает,
  галочку ставит пользователь). Коллизии имён уже решены (`-2`, `-3`).
- **F2. Типы задач.** Поле `Type:` (`brief`, `triage`, `chase`, `build`, `note`…).
  Тип = выбор инструкции из skills-файла (раздел 6), а не свободный текст.
  Неизвестный тип = `note` (деградация вместо ошибки).
- **F3. Результат.** Агент пишет `Result:` (путь к созданному/изменённому файлу +
  одна строка «что сделано») и `Source:` (на чём основано — аналог «указывает источник»
  у Duet). Телефон рендерит карточку: что/куда + Open/Undo.
- **F4. Approval-карточка.** `needs-approval` = полноэкранная карточка в mobile
  (что/куда/кому) с Approve/Deny; Deny возвращает в `new` с пометкой причины.
  Деструктивное (удаление, перезапись) без Approve не применяется никогда;
  «больше не спрашивать» для деструктивного не вводить вовсе (как у Duet).
- **F5. Журнал.** `to-agent/log.md` (append-only, пишет ПК-агент и телефон):
  взял/сделал/ждёт/отклонено. Аналог Tasks-истории + audit trail Muse.
  Читается одним проходом, сверху — последние.

Зависимости: F1 — ни от чего (можно сейчас); F3–F5 — от F1; всё — от atomic writes (C1).

## 5. Фичи: проактивность (бриф и тихие проверки)

- **F6. `chora brief` (CLI).** Одна страница на сегодня: события сегодня/завтра
  (включая repeatables) + просроченные `- [ ]` + статусы `to-agent/` (новые/готовые/ждущие).
  Plain text + `--json`. Без LLM: чистый рендер из `parse_day` + листинга.
  Это наш `/monday-brief` + `business-pulse` на минималках.
- **F7. Утренний дайджест в mobile (M2 из duet-файла).** Тот же бриф при первом
  запуске дня; тишина, если пусто (правило Duet). Собирается из `get_day_events` + листинга.
- **F8. Тихие проверки по штампу.** `storage_stamp` (C9) + каденс «утро/вечер»:
  изменилось → бейдж на табе, нет — молчать. Батарея — наш аналог «лимитов за фон».
- **F9 (позже). Follow-up по затихшему.** Duet «возвращается к тредам, которые затихли»:
  у нас это `taken` старше N дней без обновления → подсветка в брифе («висит 3-й день»).
  Дешёво (сравнение дат из имён файлов), а эффект «агент помнит» — сильный.

Не делаем: пуши «посмотри, что я нашёл» без порога важности; realtime-наблюдение;
голосовой бриф.

## 6. Фичи: слой skills (когда на ПК появится LLM-агент)

Small Business плагин Duet показывает зрелую форму: skills — «как делать типовую
работу», оркестраторы — цепочки с решением человека между шагами, `smb-onboard` —
кастомизация под бизнес. Перенос на файлы:

- **F10. Skills-файл.** `skills.md` рядом с `index.md` (тоже human-owned, агент не пишет):
  per-type инструкции (`brief: …`, `triage: …`, `chase: …`) + запреты
  («агент никогда не платит», «не пишет наружу без needs-approval», тиры из F12).
  `chora skill`-вывод ссылается на него — агент забирает инструкции сам.
- **F11 (позже). Composite-поручения.** Тип `plan-payroll`-уровня = цепочка sub-типов
  с остановкой на `needs-approval` между шагами. Только после живых F1–F5:
  цепочки без статусов и апрувов — это неконтролируемый агент.
- **F12. Тиры отправки — сейчас, одной строкой в правила.** Пока Chora ничего никуда
  не отправляет, классификатор не нужен. Но зафиксировать в `.agents/rules.md`
  и `chora/AGENTS.md`: будущий «отправить наружу» = gate с тирами
  never-share (PIN, секреты, `critical`-содержимое) vs needs-consent (остальное —
  только по явной просьбе). Права наследуются от человека (как у плагина Duet).

## 7. Фичи: mobile-экраны (раскрытие M1–M6 из duet-файла)

- **F13. Экран очереди (Tasks tab).** Список `to-agent/` с бейджами статуса,
  временем, приоритетом; tap → страница задачи (тело, результат, история из log).
- **F14. Экран результата (Make tab).** Готовое файлами: относительный путь + Open/Undo
  (паттерн уже есть в дизайн-правилах). Происхождение обязательно.
- **F15. Каналы (позже).** У Duet channels — треды под темы с общей памятью.
  У нас естественный аналог — проекты (`notes/<project>/`): фильтр очереди и брифа
  по проекту. Отдельных «каналов» не заводить, пока фильтр не станет тесен.
- **F16. `continuedMarker`-гигиена.** При делегировании черновик Capture не должен
  молча теряться (T1.2 в roadmap про несейвленные правки — та же боль с другой стороны).

## 8. Фичи: безопасность (дотянуть чтение до действий)

Грифы чтения у нас уже строже, чем у Duet (clearance-флаг, hard error на опечатку,
наследование). Не хватает симметрии на запись/действия:

- **F17. Gate на применение результата.** Любой `done` от ПК-агента, трогающий файлы
  вне `to-agent/`, применяется только после Approve (F4) либо помечается
  reversible (тогда — snackbar + Undo). Irreversible без Approve — запрещено кодом,
  не договорённостью.
- **F18. Session relock (уже в roadmap T1.7).** Смысл в оптике Duet: approval-карточка
  на разблокированном чужом телефоне = нет апрува. Пауза >60с → relock.
- **F19. «Что агент выучил» + reset.** У Duet память сбрасывается из настроек.
  У нас память — файлы, их видно; но стоит явная команда/кнопка «показать diff
  памяти за неделю» (что нового агент узнал из `to-agent/` результатов) — прозрачность
  вместо чёрного ящика.

## 9. Что НЕ делать (осознанные non-goals)

- Отдельный апп под агента (у Duet отдельность — вынужденная, preview).
- Cloud VM, чужой браузер, OAuth-зоопарк, платежи/Link, голосовой тред.
- Desktop app ради desktop app: наш «десктоп» — CLI + файлы, он уже есть.
- Multiplayer/командная работа (упрёк Vo №4): Chora — single user, one or two machines
  (`chora/AGENTS.md:4`). Не чиним то, что не обещали.
- Скорость не отдаём: любой «умный» слой — ноль новых bridge-calls в циклах,
  один range-read (C7), кэши репозиториев. Медленный умный проигрывает быстрому —
  это самый дешёвый урок из всего Duet-разбора.

## 10. Порядок (связь с существующими очередями)

1. **Сейчас, без LLM на ПК:** F1 (статусы) → F6 (`chora brief`) → F13/F14 (экраны очереди
   и результата в mobile) → F7/F8 (дайджест + тихие проверки). Параллельно C1 (atomic),
   C7 (range), C9 (stamp) — они и так в `backend-tasks.md`.
2. **Когда ПК-агент начнёт исполнять:** F2–F5 (типы, результат, approval, журнал) →
   F17 (gate на применение) → F9 (затихшее) → F19 (прозрачность памяти).
3. **Когда исполнение станет рутиной:** F10–F11 (skills + composite), F12 уже записан,
   F15 (каналы-проекты) по необходимости.
4. Каждый пункт — одна задача = один коммит, с тестом по правилам репо
   (Rust: unit + e2e; mobile: controller/domain/widget-тест; архитектура — без новых
   записей в baseline `architecture_test.dart`).

Связь файлов: этот документ — «зачем и что»; `concepts/claude-duet.md` — «у кого
подсмотрено»; `.agents/roadmap.md` + `.agents/backend-tasks.md` — «куда вставить задачи».
